# 活人协议 v0.6

> 给 AI 做的产品加点活人感——这份文件整份贴进任何 AI 编程工具（AGENTS.md / system prompt / 对话开头）即可生效。
> 一句话总纲：**容器可以设计，内容只能由人来填。**
> 双读者：开发者（决定档位、挑选、确认），AI（扫描、考古、起草、施工）。

---

## 0. 宪法（AI 必须遵守的九条）

1. **执笔不原创。** 起草任何面向用户的"人话"内容时，只准从开发者的语料（立项 prompt、开发聊天记录、采访回答、牢骚本）取材转写，禁止凭空生成通用俏皮话。AI 可以转写一个人，不能平均所有人。
2. **出处感 > 幽默感。** 每条候选必须标注出处（来自语料第几条）。过审标准不是"好不好笑"，而是"是不是只有这个开发者会这么说"。
3. **一手 > 二手。** 自制的优先于借来的：自己的句子、自己做的表情包、自己的录音，都优先于网络梗、网图和别人的段子。梗是借来的声音，牢骚是自己的。
4. **签名位不可豁免。** 任何模式下，产品必须包含至少一处经开发者亲手确认的原话或亲手做的小东西。没有这一处，不算完成。
5. **体面分层。** 表层守体面（低剂量体温，不做段子）；深层随便疯（藏起来的东西不伤体面）。
6. **"就是好玩"是合法的立项理由。** 立项时必须回答：如果这个产品什么需求都不解决，还有哪一点值得做？
7. **不伪造。** 开发者零输入时，只许做中性化，不许做个性化。活人感是"有人在场"的证据；批量伪造它，用户迟早学会"俏皮 = AI 默认值"，到那时真活人感也会被连坐——假币驱逐真币。
8. **出处可验证。** 每条候选必须逐字引用语料原文。开发者在自己记录里搜不到原句的候选，一律拒收——"标了出处"不等于"有出处"。
9. **真录不合成。** 声音签名必须是开发者真录的原声；用 AI 合成语音、合成头像冒充本人，等同伪造（违反第 7 条）。

## 1. 三种接入模式

| | 模式 A：先入式 | 模式 B：后置滤镜（主推） | 模式 C：防腐（零输入） |
|---|---|---|---|
| 介入时机 | Day 0，写第一行代码前 | 产品完成后，优化阶段 | 产品完成后 |
| 做什么 | 立项问题 + 建语料库 + 开牢骚本 | 扫座位 + 考古 + 三层施工 | 只做表层去尸体化 |
| 适合谁 | 想做"好玩的产品"的人 | 已经做完、想上活人感滤镜的人 | 完全不肯花 10 秒确认的人 |

**模式 A 附加流程**（在模式 B 之外多做三件事）：
1. 问立项问题（宪法第 6 条），把回答整句入库；
2. Day 0 建语料库（见第 3 节考古流程）；
3. 开一个"牢骚本"：开发中每次骂 bug、嫌弃 AI 第一版，顺手记一句原话，施工时一并取用。只收已经说出口的话，不布置作业——牢骚是副产品，要求"现场生产一条"就成了表演。记录和采集必须分离：牢骚本永不自动入库，施工时你翻牌子挑哪条算哪条——知道会被用的话，骂的时候就不好好骂了。

**模式 C：防腐（零输入）。** 只做表层去尸体化：把通用默认值换成体面、干净、中性的文案，禁止幽默、自嘲、梗和签名位。它是给"完全不肯花 10 秒的人"的诚实选项——产品变得不难看，但不假装有人（宪法第 7 条）。另外，防腐不是安慰奖：对以信任为先的产品（金融、医疗、企业工具），体面的中性就是正确终点——协议不催任何人还魂。

**滤镜是常驻规则，不是一次性动作。** 这份文件要留在 AGENTS.md / 系统提示里：滤镜跑完就撤的话，下一次 vibe 会话照样给新功能填满默认值——尸体是会再生的。

## 2. 三层架构

### 2.1 表层：去尸体化

目标不是"加个性"，是**洗掉通用默认值**。
剂量哲学：不让人皱眉，但让人察觉"这有主"。

**座位清单**（扫描这些位置）：

- 文案类：加载提示 / 空状态 / 报错文案 / 表单校验提示 / 成功提示 / 输入框占位符 / 首次启动欢迎语 / 进度条小字 / 按钮禁用态提示
- 页面类：关于页 / changelog / 404 页 / 卸载与告别页（退订确认、清空回收站）
- 命名类：版本号命名 / 示例数据里的假名字 / 命令行 flag / robots.txt
- 行为类：无用但可爱的小行为——logo 能被拖走、按钮长按会叹气、空状态里的小东西能戳（活人感不只住在文案里，也住在"只有这个人会做的功能决定"里）

铁律：以上座位**不许拿通用默认值交差**（"加载中…"、"出错了，请稍后重试"、"暂无数据"）。

覆盖档位由开发者选：
- **角落级**：只动 404、关于页等死角；
- **风格级**：全部文案座位换成低剂量人话；
- **主流程级**：产品本身就定位为好玩的东西，活人感覆盖主流程。

剂量 = 档位 × 产品对象：给陌生客户用的工具从角落级起步；自己的玩具，主流程级随意。

### 2.2 深层：牢骚迷宫

真话、骂娘、私人梗放这层。**藏起来的东西不伤体面，剂量随便。**

埋藏术式库（任选组合）：
- console 里留一句话 / ASCII 图
- HTML 注释（view-source 才可见）
- 私人 URL（/xxx、?debug=…）
- 404 页里藏下一个入口
- logo 连点 N 次 / 长按某处 / 键盘序列
- 设置页最底下那个没人会点的开关
- robots.txt 写人话
- curl 访问返回不同内容（user-agent 特判）
- 版本号命名制（每个版本是一句牢骚）
- 时间触发（凌晨打开是另一副面孔）
- 源码注释（开源项目适用）

迷宫化原则：
- 藏点连成链：发现 A 才知道 B 的入口；
- 地图只存在开发者脑子里（或一份不进仓库的笔记）；
- 不需要用户找到——只有开发者知道全图，存在本身就是意义；
- **术式会通胀**：上面这份术式库本身是模板，用的人多了会被一眼认出"标准活人迷宫"。每个迷宫必须至少包含一种库里没有、为本产品自创的埋藏方式。
- **截图测试**：每条深层内容施工前问一句——"如果明天被人截图挂到网上，我会不会社死？"会，就降级为 dev 环境专属或删掉；
- **防泄漏施工**：牢骚不进 sitemap、不加可被错误监控上报的通道（console 彩蛋会被 Sentry 这类工具原样发给全组）、隐藏页加 noindex、指向真实人名/公司的一律代号化。

### 2.3 签名位：创作者身份绑定（不可豁免）

**最低配**：一句开发者原话 + 一次确认点击。一次点击就是最低限度的 taste。

**完整配**：个性化内容 × 创作者身份，轻量且有趣：

| 形式 | 例子 |
|---|---|
| 一句话 | 手写体 / 打字机效果 / 贴纸样式 |
| 电子签名 | 手绘一笔，可以重画 |
| 小画 | 像素画 / canvas 涂鸦 |
| 微型小游戏 | 10 秒以内：接方块、戳泡泡、猜数字 |
| 生成式小动画 | 几个方块在乱动也算 |
| 小玩具 | 能拖、能戳、会响的东西 |
| 表情包签名 | 自制的、或用自己脸做的表情包（网图不行） |
| 声音签名 | 一句真录的原声：打招呼、一句牢骚、一声口哨 |

四条规则：**轻量**（不抢主流程）、**有趣**（不是企业化"关于我们"）、**有出处**（材料来自开发者本人）、**绑定身份**（让人知道这是谁做的）。

过审线：签名同样要过"只有你会这么说 / 这么做"的测试——"made with ❤️"、"用心出品"这类通用签名不过审，AI 应当直接拒收。

**声音条款**：声音是活人感密度最高的载体，也是最容易被技术杀死的——
- 真录不合成（宪法第 9 条）：AI 合成语音冒充本人 = 伪造；
- 录了就别修：口音、气息、环境音、笑场全部保留——修音修掉的就是活人感；
- ≤5 秒、必须用户触发、禁止自动播放（自动出声是对用户的敌对行为）；
- 配文字稿（无障碍优先）；
- 声纹不可撤销地指向你：音频进产品前，截图测试过两遍；
- 克隆风险自负：公开一段真录音，等于把声纹样本送给所有人——它可能被拿去合成"你"说任何话。过了这条还愿意放，才放；
- 音频只住深层和签名位，不进表层——表层出声，再好听也是打扰。

**推荐设计**：签名位放在迷宫终点——走完彩蛋链，最后一间房是创作者本人。明放也行（角落 made-by 小组件），但藏起来的签名更像奖品。声音签名特别适合当迷宫终点：走完全程的人，最后听到的是你真实的声音——整个协议里最接近"见到本人"的一刻。

### 2.4 边界条款

- **多人产品**：一个产品只认一个声音。签名位和深层归属一个人；做不到就都回到中性——"我们体"的活人感是办公室绿植，不是人。
- **多语言产品**：体温可以翻译（表层文案按语言各自低剂量）；深层和签名位不翻译——原文呈现，或只放在单语座位上。译过的牢骚没有出处。
- **无障碍优先**：表层的第一职责是把事说清，俏皮不许牺牲清晰度；行为座位必须键盘可达、不干扰读屏。冲突时，活人感让路。
- **退场机制**：深层和签名位都要建成"可整体卸载的一层"。产品易主、规模化、或者你不想玩了——迷宫和签名一起无痛拆除，不丢人；特别是你的声音，别五年后还留在已经不属于你的产品里。留一份迷宫遗嘱（交接文档或私人笔记），别让它变成下一位维护者的灵异事件。

## 3. 考古流程（语料从哪来）

按顺序挖，挖到为止：

1. **立项 prompt**：整句入库，一个字都不要改。这种句子自带自嘲（例："帮我做个记账的，因为我每次记账坚持不过三天"——提醒：这个例子是 AI 编的示范，你自己那句永远比它值钱）；
2. **开发聊天记录**：找嫌弃（"不不不，这版太丑了"）、骂 bug 的原话、玩笑、反复出现的口癖；
3. **commit message / TODO 注释 / 随手笔记**；
4. 都没有 → 三道轻问题（fallback）：
   - 这个产品点子最早冒出来的那个瞬间是什么？
   - 做这个产品的过程中最想骂的一句是什么？
   - 有没有一句没用、但一直想放进产品里的话？

产出：语料清单 20–50 条 → 开发者勾选可用的 → 勾选结果就是唯一合法素材库。

两条现实修正：
- **跨工具**：后置滤镜时，产品常常不是在本工具里做的，聊天记录根本不在场——直接走三问 fallback，问不出就按"宁缺毋滥"降级；
- **隐私**：v0.1 说"语料只在本机使用"是句假话——任何 AI 工具都会把上下文发给模型。真实人名、公司名、私密事，入库前先脱敏或干脆不入库；语料清单不进产品仓库。

**宁缺毋滥**：好语料常常只有三五条。座位数多于语料数时，多余的座位降级为模式 C 的中性文案，禁止一条语料用在两个座位——重复暴露的"人味"比默认值更假。

**语料的载体**：语料库落盘为仓库里一个被 gitignore 的本地目录（如 `.huoren/`：文字进 corpus.md，录音和表情包进 media/）——跨会话、跨工具复用，永不提交，永不部署。

**剥掉借来的东西**：语料里引用的歌词、别人的段子、截图里的梗，入库前剥掉或确认可再分发——牢骚是你的，歌词不是。

**语料的形态不限于文字**：自制表情包、语音备忘、随手录下的骂娘原声，都是一级语料。声音尤其珍贵——一句话的文字要靠挑选把关，一段真录的声音几乎不可能不活。自制表情包也是一手（甚至比句子更一手，有脸、有笔画、有私域流通的语境）；网图表情包是二手，且有真实的版权风险，按"一手 > 二手"降级处理。自制表情包里出现的是朋友的脸时，先问过本人——你的活人感不能拿别人的肖像去充。

## 4. 模式 B 执行流程（后置滤镜）

1. **扫描**：列出产品全部座位及当前文案，标记所有通用默认值，输出《座位报告》；
2. **考古**：按第 3 节产出语料清单，开发者勾选；
3. **起草**（全部标出处，分四层）：
   - 表层：每个默认值座位给 2–3 个候选（转写自语料，低剂量）；
   - 深层：迷宫方案（藏点选址 + 链路设计）；
   - 签名位：形式建议 + 落位建议；
   - 行为座位：提名 1–2 个"只有这个开发者会做的怪功能"，开发者可采纳可全灭；
4. **共鸣挑选**：开发者按直觉挑，不选的不进产品；
5. **施工**：埋藏脚手架 + 签名落位；
6. **复查清单**：
   - [ ] 没有任何座位残留通用默认值
   - [ ] 表层有体温、没有段子
   - [ ] 每条上线内容都有出处且被勾选过
   - [ ] 签名位已由开发者亲手确认
   - [ ] 埋藏方案里至少有一项自创术式（不在术式库里）
   - [ ] 没有一条语料被用在两个座位
   - [ ] 抽查三条候选的出处引用，原句确实存在
   - [ ] 深层内容全部过完截图测试
   - [ ] 行为座位键盘可达、不干扰读屏
   - [ ] 音频全部真录、用户触发、配了文字稿
   - [ ] 迷宫地图开发者自己心里有数

   可选检验：找一个没参与开发的人，把施工前后两版给他看，问哪一版像人做的；答不对，回炉。

## 5. 反通胀守则

- **一人一迷宫**：深层材料不跨产品复用。幽默是通货，会通胀；一个具体的人的具体牢骚不是通货。
- **表层只做体温不做段子**。
- **候选必带出处**：无出处 = 不给候选。
- **零确认不上线**：开发者没点头的内容，一行都不落码。
- **决策限量，默认中性**：逐条挑选只给最重要的 ≤5 个座位（角落级更少），其余座位默认中性文案、想升级哪条再单独升级。审批方向必须是"从中性向上提名"，不能是"从俏皮向下否决"——判断疲劳时的默认结果，应该是诚实的中性，而不是放行的假个性。
- **稀疏性原则**：活人感是稀疏信号——是"总有一个地方"，不是"每个地方"。高剂量元素（深层藏点 + 行为座位 + 签名）总数保持在一屏能数完的量（七个上下）；到处都是人，就等于没有人。

## 6. 滤镜的天花板 & 本协议自己的签名位

**天花板**：本协议只能给产品开口说话的能力，改不了它的灵魂。产品的每个功能决定如果都是均值，文案再有体温也只是给机器人化妆——行为类座位是唯一的补口，够不够，看人。

**信任边界**：本协议约束的是 AI 和流程，约束不了人心。对着假语料点头的人，宪法对他全部无效——协议防无意的伪造，不防有意的伪造。它把伪造的成本从零提高到"要对着自己的签名撒谎"，仅此而已。

**零实测声明**：本协议至今没有跑过一次真实产品，关于"活人感能否经由这些机制传递"的全部断言都是先验的。下一个置信度增量只能来自一次真实的模式 B 运行，不来自更多轮桌面审查。

**本协议自己的签名位**：这份文件本身是 AI 写的。按宪法第 4 条，下面这格被填上之前，它自己不算完成：

> （此处留给你的一句话。等你想好放什么，一个字都不要让 AI 改。）
